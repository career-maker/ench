# Enchantive Asia – static website (HTML + Sass)

Implementation of the approved homepage design (`Design.pdf`) plus inner pages.

## Install / build / run
```bash
npm install            # installs sass + font packages
npm run build          # sass -> css/main.css + css/main.min.css, then builds HTML pages
npm run sass:watch     # recompile CSS on change
npm run serve          # http://localhost:8080 (works over file:// too)
npm run check          # verifies local links, anchors and duplicate ids
```

## Structure
- `src/pages/*.html` – page bodies (first line is a JSON comment with title/description/nav key).
- `src/partials/` – `header.html`, `footer.html`, `cta.html` (closing CTA, exact supplied copy), `sprite.html` (SVG icons).
- `scripts/build-pages.mjs` – injects partials and writes the root `*.html` files. **Edit `src/`, never the root HTML.**
- `scss/` – abstracts, base, layout, components, pages; `main.scss` is the entry point. HTML loads `css/main.min.css`.
- `js/` – Classic scripts (load order matters): `navigation.js`, `forms.js`, `animation.js` (no third-party libraries).
- `assets/` – optimised WebP images, logos, self-hosted fonts.
- `scripts/overflow-test.html`, `scripts/func-test.html` – browser test harnesses (serve and open them).

## Before production
1. **Indexing**: pages ship with `<meta name="robots" content="noindex, nofollow">` (staging). Set `STAGING = false` in `scripts/build-pages.mjs`, rebuild, and confirm the canonical base `SITE` is correct.
2. **Contact form** (`contact.html`): no backend is configured. Add `data-endpoint="https://…"` to the `<form>` (Formspree, Getform, a serverless function or CMS handler accepting multipart POST returning 2xx). Until then the form validates and states honestly that nothing was sent.
3. **Server headers** (must be set on the host; not verifiable locally): `Content-Security-Policy` (`default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'self'; font-src 'self'`), `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`. The site uses no inline scripts/styles beyond a one-line `no-js` class toggle in `<head>` – add its hash to the CSP or move it to a file.
4. Replace draft copy, placeholder testimonials/stats, social icon links, founder section (see `docs/content-notes.md`).
5. Run PageSpeed Insights against the staging URL (see `docs/qa-report.md`).

## WordPress readiness
Header/footer/CTA are partials, page bodies are section-based with BEM classes, CSS has no page-level coupling beyond `pages/_*.scss`. Convert partials to `header.php`/`footer.php` and each `src/pages/*.html` to a page template.

## Beta status
The site is in beta: every page has `noindex, nofollow`, `robots.txt` disallows all crawling and `.htaccess` sends `X-Robots-Tag`. To launch: set `STAGING = false` in `scripts/build-pages.mjs`, replace `robots.txt` with `docs/robots.production.txt`, remove the X-Robots-Tag lines from `.htaccess`, rebuild. `sitemap.xml` is generated by `npm run build`. Legal pages (`privacy.html`, `terms.html`) are drafts needing legal review.

Git push details are kept locally in `.deploy/` (git-ignored): `.deploy/push.ps1 "message"` or `bash .deploy/push.sh "message"`.
